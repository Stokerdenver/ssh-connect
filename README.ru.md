# SSH-Connect

[English](README.md) | **Русский**

> Форк [mixelpixx/SSH-Connect](https://github.com/mixelpixx/SSH-Connect) (лицензия MIT).
> В нём добавлен локальный веб-интерфейс для сохранённых хостов, пароли больше не
> проходят через чат, и исправлены проблемы безопасности, перечисленные ниже. Всё
> остальное — 38 инструментов, скиллы и агенты — работает как в оригинале.

## Что изменено в этом форке

### Веб-интерфейс для сохранённых хостов

Запустите `ssh-connect ui` или дважды щёлкните `ssh-connect.exe`. В браузере откроется
страница, где можно добавлять, изменять и удалять хосты — название, адрес, порт,
пользователь, пароль **или** приватный ключ (+ пароль ключа), enable-пароль для сетевого
оборудования, описание для агента — и проверять каждый кнопкой **«Проверить подключение»**.

- Агент видит только названия хостов. Он вызывает `list_hosts`, затем
  `ssh_connect {host: "qa1"}` или `connect {name: "switch"}`; `login` / `enable` сами
  берут сохранённые пароли.
- Пароли хранятся в **диспетчере учётных данных Windows** (на других ОС — в
  `~/.ssh-connect/secrets.json` с правами 0600), и читает их сам сервер. Они не проходят
  через модель, чат и LLM-провайдера.
- Изменения действуют сразу, перезапускать MCP-клиент не нужно: сервер перечитывает
  список хостов при каждом вызове.
- Страница слушает только `127.0.0.1` на случайном порту и требует токен текущего запуска
  из ссылки, которую выводит консоль. Она проверяет заголовки `Host` / `Origin`, отдаёт
  строгую Content-Security-Policy и умеет задавать и удалять секреты, но никогда их не
  показывает.

Подробнее: [Сохранённые хосты и веб-интерфейс](#сохранённые-хосты-и-веб-интерфейс).

### Исправленные проблемы безопасности

| Проблема в оригинале | Исправление в форке |
|---|---|
| Инструменты передачи файлов (`ssh_upload_file`, `ssh_download_file`, `ubuntu_website_deployment`, `upload_config`, `download_config`, `switch_backup_config.save_to`) читали и записывали **любой** локальный путь. Агент, получивший prompt injection, мог выгрузить `~/.ssh` на произвольный хост или положить файл в папку автозагрузки Windows. | Локальные пути ограничены одной папкой обмена (по умолчанию `~/ssh-connect-files`). Выход за её пределы через `..`, символические ссылки и junction запрещён. |
| Ключи хостов: `ssh_connect` по умолчанию принимал любой ключ, а интерактивный `connect` не проверял их вовсе, поэтому пароли можно было перехватить атакой «человек посередине». | Проверка trust-on-first-use включена по умолчанию для обоих путей. Изменившийся ключ отклоняется, сбросить его можно в интерфейсе. |
| `connect {name, host}` брал сохранённый пароль хоста `name` и отправлял его на адрес, выбранный агентом. | Сохранённые хосты закреплены: адрес, порт и протокол нельзя переопределить, а сохранённые секреты используются только для сохранённого пользователя. |
| `hosts.toml` читался из текущей папки, поэтому склонированный репозиторий мог перенаправить имена хостов на другие адреса. | Список хостов хранится только в `~/.ssh-connect/` (или там, куда указывает `SSHCONNECT_HOSTS`). |
| Пароли можно было передать только аргументами инструментов, то есть через модель и историю чата. | Пароли лежат в хранилище учётных данных ОС; `list_hosts` сообщает только, сохранён ли пароль. |
| Внедрение shell-команд через параметры инструментов: права в `chmod`, пользователь crontab, юнит `journalctl`, сигнал `kill`, имя сайта nginx (выход за пределы каталога через `sudo cp`), имя базы MySQL, домены в проверке здоровья. | Все эти значения экранируются или проверяются; временный файл nginx создаётся через `mktemp`. |
| Именованный канал / сокет брокера принимал любую локальную учётную запись, и тот, кто создал его первым, получал все пересылаемые вызовы инструментов. | Собеседник должен работать от того же пользователя ОС; удалённые клиенты канала отклоняются; Unix-сокет получает права `0600`. |

**Известные ограничения.** Для крейта `rsa` есть уведомление RUSTSEC-2023-0071, у
которого нет исправления, — используйте ключи ed25519. Ключи из ssh-agent предлагаются
любому хосту, к которому вы подключаетесь. Главной защитой по-прежнему остаётся
подтверждение каждого вызова в MCP-клиенте: не включайте для этого сервера «Always allow».

## О сервере

Сервер [Model Context Protocol](https://modelcontextprotocol.io) (MCP) на Rust для
администрирования удалённых серверов и интерактивного управления сетевыми устройствами и
консолями по **SSH, Telnet и Serial**, с набором готовых скиллов и агентов. Один бинарник
решает два вида задач:

- **Серверные операции** — администрирование Linux/Ubuntu (nginx, SSL/certbot, UFW,
  пакеты, деплой, systemd, MySQL/MariaDB, Redis, Docker, логи, процессы, файлы, cron).
  Каждая команда выполняется в собственном SSH-канале и возвращает код завершения;
  передача файлов идёт по SFTP; проверка ключа хоста по схеме trust-on-first-use
  включена по умолчанию.
- **Интерактивная консоль** — управление коммутаторами, маршрутизаторами и консолями с
  распознаванием приглашения по SSH (PTY), Telnet и Serial: обработка постраничного
  вывода, сценарии enable/login, команды на группу устройств. Брокер (именованный канал
  Windows / Unix domain socket) позволяет нескольким MCP-клиентам пользоваться одним
  набором живых сессий и последовательных портов.

Построен на MCP SDK `rmcp`. SSH реализован на чистом Rust через `russh` (без
зависимости от OpenSSL/C).

**Скачать:** готовые бинарники для Linux, macOS и Windows лежат на
[странице релизов](https://github.com/Stokerdenver/ssh-connect/releases/latest) — для
запуска не нужен тулчейн Rust.

## Две модели работы, один сервер

| Задача | Семейство инструментов | Подключение | Выполнение |
|--------|------------------------|-------------|------------|
| Администрирование Linux/VPS с кодами завершения | server-ops | `ssh_connect` | `ssh_exec`, `vps_*`, `ubuntu_*` |
| Коммутаторы, маршрутизаторы, консоли, serial | интерактивная консоль | `connect` | `run_command`, `enable`, `login` и др. |

Оба семейства работают в одном процессе и используют общий брокер, поэтому сессия,
открытая одним MCP-клиентом, доступна из другого.

## Инструменты

- **Сессии / обнаружение (интерактив):** `connect`, `disconnect`, `list_sessions`,
  `list_com_ports`, `list_hosts`
- **Интерактивные команды:** `run_command`, `run_commands`, `enable`, `login`,
  `expect_send`, `run_on_fleet`, `upload_config`, `download_config`
- **Удобные команды для коммутаторов:** `switch_backup_config`,
  `switch_network_diagnostics`
- **SSH server-ops:** `ssh_connect`, `ssh_exec`, `ssh_upload_file`, `ssh_download_file`,
  `ssh_list_files`, `ssh_disconnect`
- **VPS / Ubuntu:** `vps_system_stats`, `vps_logs`, `vps_process`, `vps_file_read`,
  `vps_file_ops`, `vps_cron`, `ubuntu_service_control`, `vps_nginx_config`,
  `ubuntu_nginx_control`, `ubuntu_update_packages`, `ubuntu_ssl_certificate`,
  `ubuntu_website_deployment`, `ubuntu_ufw_firewall`, `ubuntu_mysql`, `vps_redis`,
  `vps_docker`, `vps_health_check`

По таймауту `ssh_exec` (и инструменты `vps_*`/`ubuntu_*`) возвращают ошибку и пытаются
завершить удалённую команду. Это не гарантировано — OpenSSH может проигнорировать сигнал
в exec-канале без PTY. `ubuntu_update_packages`, `ubuntu_ssl_certificate` и `vps_docker`
принимают необязательный `timeoutMs`. Операции, которые могут идти минутами, лучше
запускать в фоне и опрашивать лог-файл, а не полагаться на длинный таймаут (см. скилл
`vps-management`).

## Скиллы (`skills/`)

- **switch-management** — практические рекомендации по коммутаторам/маршрутизаторам:
  особенности вендоров, постраничный вывод, enable/config, сохранение, операции над
  группой устройств, обновление прошивки, настройка SSH через консоль.
- **vps-management** — дисциплина безопасных изменений и стандартные сценарии
  (обновление + перезагрузка, разбор проблем SSL/certbot, восстановление сервисов,
  опрос долгих операций).
- **vps-health-report** — стандартизированный HTML-отчёт о состоянии сервера (плюс JSON
  и сравнение с прошлым отчётом) на основе `vps_health_check`.
- **health-report** — стандартизированный HTML-отчёт о состоянии сетевых устройств
  (плюс JSON).

## Сборка

Нужен актуальный стабильный тулчейн Rust. Зависимости (включая `rmcp = "1.8"` с
crates.io) Cargo скачает сам.

```sh
cargo build --release
# Бинарник: target/release/ssh-connect  (ssh-connect.exe в Windows)
```

Windows и macOS не требуют системных пакетов. В **Linux** крейту `serialport`
(используется в `list_com_ports` и для serial-консоли) при сборке нужен `libudev`:

```sh
sudo apt-get install -y libudev-dev pkg-config   # Debian/Ubuntu
```

Не хотите собирать сами? Готовые бинарники для Linux, macOS и Windows прикладываются к
каждому релизу на [странице релизов](https://github.com/Stokerdenver/ssh-connect/releases/latest)
(их собирает GitHub Actions workflow `release`).

## Подключение к MCP-клиенту

Claude Code:

```sh
claude mcp add ssh-connect --scope user -- /path/to/ssh-connect/target/release/ssh-connect
```

Или в файле настроек MCP:

```json
{
  "mcpServers": {
    "ssh-connect": {
      "command": "/path/to/ssh-connect/target/release/ssh-connect"
    }
  }
}
```

Сервер работает по MCP через stdio; все логи идут в stderr (задайте `RUST_LOG=info`,
чтобы видеть сообщения брокера и выбранную роль).

В примерах ниже замените путь на расположение своего бинарника. В Windows указывайте
`ssh-connect.exe` и экранируйте обратные слэши в JSON
(`"C:\\Tools\\ssh-connect\\ssh-connect.exe"`) либо используйте прямые слэши. Благодаря
брокеру можно одновременно держать открытыми несколько клиентов (например, VS Code и
OpenCode) — они будут работать с одними и теми же живыми сессиями.

### VS Code

**GitHub Copilot (режим агента).** Добавьте сервер для текущего рабочего пространства в
`.vscode/mcp.json` (обратите внимание: ключ верхнего уровня — `servers`, а не
`mcpServers`):

```json
{
  "servers": {
    "ssh-connect": {
      "type": "stdio",
      "command": "/path/to/ssh-connect",
      "env": { "RUST_LOG": "info" }
    }
  }
}
```

Чтобы сервер был доступен во всех проектах, выполните в палитре команд
**MCP: Open User Configuration** и добавьте ту же запись, либо зарегистрируйте его из
терминала:

```sh
code --add-mcp "{\"name\":\"ssh-connect\",\"command\":\"/path/to/ssh-connect\"}"
```

Затем откройте Copilot Chat, переключитесь в режим **Agent** и включите инструменты
`ssh-connect` в списке инструментов. Команда **MCP: List Servers** показывает статус
сервера и его логи.

**Расширение Claude Code.** Расширение использует ту же конфигурацию, что и CLI, поэтому
достаточно команды `claude mcp add ...` выше. Для сервера уровня проекта положите в корень
репозитория `.mcp.json` с блоком `mcpServers`, показанным выше.

**Cline.** Нажмите значок **MCP Servers** на панели Cline → **Configure** →
**Configure MCP Servers**; откроется `cline_mcp_settings.json`:

```json
{
  "mcpServers": {
    "ssh-connect": {
      "command": "/path/to/ssh-connect",
      "args": [],
      "env": {},
      "disabled": false,
      "alwaysAllow": []
    }
  }
}
```

Оставьте `alwaysAllow` пустым (или перечислите в нём только инструменты для чтения, например
`list_hosts`, `list_sessions`, `vps_system_stats`), чтобы любая команда, меняющая
состояние, требовала вашего подтверждения.

**Roo Code.** Тот же формат `mcpServers` — глобально через настройки MCP на панели Roo
(**Edit Global MCP**) или для проекта в `.roo/mcp.json`.

**Continue.** Создайте в рабочем пространстве файл `.continue/mcpServers/ssh-connect.yaml`
(инструменты MCP доступны в режиме Agent):

```yaml
name: SSH-Connect
version: 0.0.1
schema: v1
mcpServers:
  - name: ssh-connect
    command: /path/to/ssh-connect
    args: []
```

### OpenCode

Добавьте сервер типа `local` в ключ `mcp` файла `opencode.json` — в корне репозитория
(для проекта) или в `~/.config/opencode/opencode.json` (глобально). `command` — это
**массив** (бинарник и аргументы):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "ssh-connect": {
      "type": "local",
      "command": ["/path/to/ssh-connect"],
      "enabled": true,
      "timeout": 10000,
      "environment": { "RUST_LOG": "info" }
    }
  }
}
```

Проверить подключение можно командой `opencode mcp list`. Инструменты появляются под
именами `ssh-connect_<tool>`; их можно ограничить для отдельных агентов через секции
`tools` / `permission` конфига (например, поставить для опасных инструментов `"ask"`).

### OpenClaw

OpenClaw берёт MCP-серверы из блока `mcp.servers` файла `~/.openclaw/openclaw.json`
(JSON5):

```json5
{
  mcp: {
    servers: {
      "ssh-connect": {
        command: "/path/to/ssh-connect",
        args: [],
        env: { RUST_LOG: "info" },
      },
    },
  },
}
```

После правки перезапустите gateway и проверьте командами `openclaw mcp list` /
`openclaw mcp show ssh-connect`. Тот же блок можно редактировать из Control UI
(`/settings/mcp`). К OpenClaw часто обращаются из мессенджеров, поэтому подумайте, кто
может писать агенту: SSH-Connect способен менять удалённые системы, а сохранённые хосты
дают ему доступ без запроса пароля. Ограничьте агента через `toolFilter` (списки
include/exclude) или заведите для него отдельный набор хостов только для чтения.

### Как пользоваться

После подключения просто попросите агента обычным языком, например: *«Покажи сохранённые
хосты и загрузку диска и памяти на web-01»* или *«Сделай бэкап running-config с
core-sw-01»*. Заранее добавьте серверы через `ssh-connect ui` (см. ниже), чтобы агенту
никогда не требовались пароли в чате. Скиллы из `skills/` — это обычный Markdown: в
клиентах без встроенной поддержки скиллов их можно подключить как контекст или как
пользовательские инструкции/правила.

## Сохранённые хосты и веб-интерфейс

Запустите `ssh-connect ui` (или просто дважды щёлкните `ssh-connect.exe`), чтобы открыть
локальную страницу управления сохранёнными хостами: имя, адрес, порт, пользователь,
пароль **или** приватный ключ (+ парольная фраза), enable-пароль для сетевого
оборудования, описание для агента и кнопка «проверить подключение». Страница слушает
только `127.0.0.1`, и каждый запрос требует токен текущего запуска из ссылки, выведенной
в консоль.

- Хосты хранятся в `~/.ssh-connect/hosts.toml` (`%USERPROFILE%\.ssh-connect\hosts.toml`),
  а не в текущем каталоге. Сервер перечитывает файл при каждом вызове, поэтому хост,
  добавленный в UI, доступен сразу — перезапускать MCP-клиент не нужно.
- Пароли, парольные фразы и enable-пароли сохраняются в **диспетчере учётных данных
  Windows** (общие учётные данные `ssh-connect:<kind>:<host>`), на других ОС — в
  `~/.ssh-connect/secrets.json` (права 0600). Страница может задать или удалить их, но
  никогда не показывает.
- Агент вызывает `list_hosts`, затем `ssh_connect {host: "<name>"}` или
  `connect {name: "<name>"}`; если `password` не передан, `login`/`enable` берут
  сохранённые секреты. Секреты никогда не проходят через модель, чат или канал брокера.
- Сохранённый хост **закреплён**: его адрес, порт и протокол нельзя переопределить
  аргументами инструмента, а его секреты используются только для его собственного
  пользователя — поэтому агент, получивший prompt injection, не сможет отправить их
  куда-то ещё.

### Быстрый запуск в Windows

При каждом запуске у страницы новый порт и новый ключ доступа, поэтому сохранить её в
закладки нельзя. Удобнее запускать её ярлыком: браузер откроется сам с правильной ссылкой.

**Ярлык в меню «Пуск» с горячей клавишей.** Один раз выполните в PowerShell (путь в
`$exe` замените на свой):

```powershell
$exe = "C:\Tools\ssh-connect\ssh-connect.exe"
$lnk = "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\SSH-Connect.lnk"
$s = (New-Object -ComObject WScript.Shell).CreateShortcut($lnk)
$s.TargetPath       = $exe
$s.Arguments        = "ui"
$s.WorkingDirectory = Split-Path $exe
$s.Description      = "SSH-Connect — управление хостами"
$s.Hotkey           = "CTRL+ALT+S"
$s.WindowStyle      = 7          # консоль сразу свёрнута, открывается только браузер
$s.Save()
```

После этого интерфейс открывается сочетанием **Ctrl+Alt+S**, через «Пуск» (набрать
`SSH-Connect`) или с панели задач, если закрепить ярлык (правый щелчок по нему в «Пуске» →
«Закрепить на панели задач»). Не закрывайте свёрнутую консоль, пока работаете со
страницей; остановить интерфейс можно ссылкой «Остановить интерфейс» внизу страницы или
закрыв консоль. Если сочетание занято, укажите другое (например, `"CTRL+ALT+H"`) и
выполните скрипт заново.

**Команда в PowerShell.** Добавьте в профиль (`notepad $PROFILE`):

```powershell
function sshui { & "C:\Tools\ssh-connect\ssh-connect.exe" ui }
```

Тогда в любом новом окне PowerShell интерфейс открывается командой `sshui`.

## Настройка

- **Инвентарь:** управляется через `ssh-connect ui`, либо правьте
  `~/.ssh-connect/hosts.toml` вручную (см. `hosts.example.toml`). Путь можно
  переопределить через `SSHCONNECT_HOSTS`.
- **Секреты через переменные окружения (необязательно):** для хоста `core-sw-01`
  переменная `SSHCONNECT_CORE_SW_01_PASSWORD` (имя в верхнем регистре, все
  неалфавитно-цифровые символы схлопываются в `_`) переопределяет сохранённый пароль;
  так же работают `_PASSPHRASE`, `_ENABLE_PASSWORD`, `_USERNAME`, `_HOST`, `_PORT`,
  `_KEY_PATH`.
- **Проверка ключа хоста (оба SSH-пути):** trust-on-first-use по
  `~/.ssh-connect/known_hosts` **по умолчанию** — первый увиденный ключ запоминается,
  последующее несовпадение отклоняется. Сбросить ключ переустановленного устройства можно
  в UI («Забыть ключ хоста»). Отключается в настройках UI или через
  `SSHCONNECT_HOST_KEY_CHECK=off`.
- **Папка обмена:** инструменты, которые читают или пишут локальные файлы
  (`ssh_upload_file`, `ssh_download_file`, `ubuntu_website_deployment`, `upload_config`,
  `download_config`, `switch_backup_config.save_to`), работают только внутри одной
  папки — по умолчанию `~/ssh-connect-files`, меняется в UI или через
  `SSHCONNECT_TRANSFER_DIR`. Относительные пути разрешаются внутри неё; `..` и ссылки,
  ведущие наружу, отклоняются.
- **Конфиг SSH-клиента:** разбор делегирован локальному клиенту OpenSSH — оба
  инструмента подключения выполняют `ssh -G <host>` и используют полученные HostName,
  User, Port и IdentityFile, поэтому блоки `Host`/`Match`, `Include`, шаблоны,
  процентные токены, канонизация и собственные умолчания OpenSSH (User = локальная
  учётная запись, Port 22) работают ровно так же, как для самого `ssh`. Явные аргументы
  и записи в `hosts.toml` имеют приоритет. Если `ssh` нет в PATH, определяется только
  имя локальной учётной записи.
- **ssh-agent:** ключи из агента предлагаются после пароля и файла ключа. В Unix сокет
  берётся из `SSH_AUTH_SOCK`; в Windows, если переменная не задана, используется
  именованный канал OpenSSH (`\\.\pipe\openssh-ssh-agent`). Передайте
  `useAgent: false` (`use_agent` для `connect`), чтобы принудительно использовать
  конкретные учётные данные. RSA-ключи подписываются самым стойким хешем, который
  объявляет сервер, поэтому аутентификация через агент работает и с OpenSSH 8.8+,
  отвергающим SHA-1 `ssh-rsa`.

## Брокер (общие сессии для нескольких экземпляров)

Первый запущенный экземпляр становится владельцем общей для машины точки встречи —
именованного канала (`\\.\pipe\ssh-connect-broker-v1`) в Windows или Unix domain socket в
`$XDG_RUNTIME_DIR` (при его отсутствии — во временном каталоге) в Linux/macOS — и держит
живые подключения и COM-порты. Последующие экземпляры работают как прокси и пересылают
`tools/call` владельцу, так что сессия, открытая в одном клиенте, доступна в другом, а
два клиента не могут одновременно захватить один последовательный порт. Схемы
инструментов каждый экземпляр отдаёт сам. На платформе без обоих транспортов каждый
экземпляр работает как самостоятельный владелец.

Перед подключением в роли прокси экземпляр проверяет, что точку встречи обслуживает тот
же пользователь ОС (Windows: SID токена сервера канала; Unix: `SO_PEERCRED`), поэтому
другая учётная запись не может занять общеизвестное имя и перехватывать пересылаемые
вызовы.

Ограничение: если процесс-владелец завершается, существующие прокси пока не выбирают
нового владельца посреди сессии — перезапустите затронутый клиент. Вновь запущенный
экземпляр всегда выбирает роль корректно (и удаляет устаревший сокет).

## Тесты

```sh
cargo test --bin ssh-connect
```

Юнит-тесты покрывают парсер Telnet IAC, обработку приглашений и ANSI в выводе, инвентарь
хостов, разрешение алиасов через `ssh -G`, опрос последовательных портов и набор
устаревших SSH-алгоритмов. Протокол и брокер проверяются отправкой последовательности
`initialize` + `tools/list` бинарнику и запуском двух экземпляров для проверки выбора
владельца/прокси.
